# 多账号复盘与 Leader 指导 Agent — 产品需求文档（PRD）

> 版本：v1.0 | 日期：2026-08-29 | 状态：可演示 Demo

---

## 一、业务目标

### 1.1 背景与痛点

内容团队管理多个 X（Twitter）账号时，Leader 和运营同学普遍面临以下问题：

| 痛点 | 具体表现 | 现有解法的不足 |
|------|----------|----------------|
| **多账号复盘靠人工** | Leader 每周手动翻每个账号的数据，凭感觉判断问题 | 耗时、不系统、问题归因主观，容易遗漏隐性问题 |
| **问题定位不精准** | 账号表现差，但说不清是内容质量、选题、定位、发布节奏还是互动的问题 | 归因模糊，导致行动建议跑偏，治标不治本 |
| **行动建议空泛** | 复盘会上说"加强内容质量""多互动"，但没有具体可执行的动作 | 建议不可落地，下周还是老样子，复盘流于形式 |
| **一对一沟通无准备** | Leader 和运营同学 1on1 时，没有结构化的沟通提纲，聊到哪算哪 | 沟通效率低，问题谈不透，改进方向不明确 |
| **缺乏持续追踪** | 上周提的建议有没有执行？执行后有没有改善？没人跟进 | 问题反复出现，复盘变成"每周说同样的话" |

### 1.2 目标

构建一个 **多账号复盘与 Leader 指导 Agent**，实现：

1. **自动化多账号诊断**：定期采集至少 3 个账号的内容和表现数据，自动识别每个账号最主要的 1-3 个问题
2. **精准问题归因**：将问题归类到 6 大维度（内容质量、选题、定位、发布节奏、互动、账号健康），给出数据支撑
3. **可执行行动建议**：针对每个账号的问题，输出下周应执行的具体动作（不是空泛建议，而是可操作、可验证的）
4. **Leader 指导提纲**：自动生成 Leader 与运营同学 1on1 沟通的结构化提纲，提升沟通效率
5. **每日报告与评分**：每日生成账号表现报告，对每个账号进行整体评分，趋势一目了然
6. **执行追踪闭环**：持续追踪建议是否执行、执行后是否带来改善，形成"诊断→建议→执行→验证"的完整闭环

### 1.3 成功指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 复盘效率提升 | ≥ 5x | 单周多账号复盘时间从人工 4h 降至 0.8h 以内 |
| 问题归因准确率 | ≥ 85% | Agent 诊断的问题与 Leader 人工判断一致的比例 |
| 行动建议执行率 | ≥ 70% | 每周建议中被实际执行的比例 |
| 1on1 沟通效率 | ≥ 2x | 单次 1on1 有效信息密度提升，沟通时间缩短 |
| 账号表现改善率 | ≥ 60% | 执行建议后，账号核心指标有正向改善的比例 |

### 2.2 核心功能模块

#### 模块①：多账号数据采集与汇总

**输入**：至少 3 个指定 X 账号 ID + 时间范围（默认近 7 天/30 天）

**采集指标**：
- 内容数据：发文数量、发文类型分布（原创/转发/回复/Thread）、平均长度
- 表现数据：总点赞、总转发、总回复、平均互动率、最高/最低表现内容
- 发布节奏：发布频率、发布时段分布、发文间隔规律
- 互动数据：回复率、回复响应时间、与粉丝互动的深度
- 账号健康：粉丝增减趋势、掉粉率、被举报/限流迹象（如有）

**输出**：标准化的多账号数据看板（JSON + 可视化数据表）

---

#### 模块②：账号诊断 — 识别 1-3 个主要问题

对每个账号，基于数据自动识别最突出的 1-3 个问题。

**诊断逻辑**：
1. 计算各维度指标的健康分（与行业基准/账号历史基线对比）
2. 识别低于阈值的维度，标记为潜在问题
3. 按影响程度排序，取最严重的 1-3 个作为主要问题
4. 每个问题附带：问题描述、数据证据、影响评估

**问题输出格式**：
```json
{
  "account_id": "xxx",
  "problems": [
    {
      "problem_id": "p001",
      "severity": "high",  // high/medium/low
      "title": "互动率持续偏低",
      "description": "近7天平均互动率仅1.2%，低于行业基准3.5%",
      "evidence": ["近7天10条内容平均点赞23", "回复率仅0.3%", "最高表现内容互动也未超过50"],
      "impact": "账号权重下降，内容触达减少，形成恶性循环"
    }
  ]
}
```

---

#### 模块③：问题归因 — 6 大维度定位

将每个问题精准归因到以下 6 大维度之一（或多个）：

| 维度 | 判断标准 | 典型表现 |
|------|----------|----------|
| **内容质量** | 内容深度、原创性、表达清晰度 | 内容浅尝辄止、同质化严重、错别字多、无信息量 |
| **选题** | 选题与受众匹配度、时效性、差异化 | 选题偏离账号定位、追热点但不相关、受众不感兴趣 |
| **定位** | 账号人设一致性、领域专注度、辨识度 | 内容领域跳跃、人设模糊、与竞品无差异 |
| **发布节奏** | 发布频率、时段、间隔规律 | 发布不稳定（一天5条然后断更3天）、时段不在受众活跃期 |
| **互动** | 回复率、响应速度、互动深度 | 不回复评论、回复模板化、不主动与粉丝/同行互动 |
| **账号健康** | 粉丝趋势、违规记录、平台权重 | 持续掉粉、被限流、有违规记录、账号被标记 |

**归因方法**：
- 规则引擎：基于指标阈值的初步归因（如发布频率方差大→发布节奏问题）
- LLM 深度归因：结合内容样本和数据，由 LLM 判断根本原因
- 多维度关联：一个问题可能涉及多个维度，标注主因和次因

---

#### 模块④：行动建议 + Leader 指导提纲

**行动建议**（每个账号下周应执行的具体动作）：

针对每个问题，输出 **SMART 原则** 的具体行动：
- **S**pecific：具体做什么（不是"加强互动"，而是"每条内容发布后2小时内回复前5条评论"）
- **M**easurable：可衡量（"回复率提升到2%以上"）
- **A**chievable：可实现（不超出运营同学能力范围）
- **R**elevant：与问题强相关
- **T**ime-bound：有时间节点（"下周内完成"）

**行动输出格式**：
```json
{
  "account_id": "xxx",
  "actions": [
    {
      "action_id": "a001",
      "linked_problem": "p001",
      "priority": "P0",
      "action": "每条内容发布后2小时内，主动回复前5条评论，回复需包含具体内容而非模板化感谢",
      "expected_outcome": "回复率从0.3%提升到1.5%以上",
      "deadline": "下周五前",
      "difficulty": "low"
    }
  ]
}
```

**Leader 指导提纲**（1on1 沟通用）：

为 Leader 生成与运营同学的一对一沟通提纲，结构包括：
1. **开场**：本周账号整体表现总结（数据+评分）
2. **亮点肯定**：做得好的地方（先肯定再提问题，避免纯批评）
3. **问题探讨**：1-3 个主要问题，引导运营同学自己分析原因（苏格拉底式提问）
4. **行动共识**：下周具体动作，与运营同学达成一致
5. **资源支持**：运营同学需要什么帮助（内容素材、工具、培训等）
6. **收尾**：鼓励 + 下次沟通时间

---

#### 模块⑤：每日报告与账号评分

**每日报告**（自动生成）：
- 每个账号昨日核心数据（发文数、互动量、粉丝变化）
- 与前日/上周同期对比
- 异常预警（数据骤降、掉粉异常、内容表现异常）
- 待办提醒（有哪些建议动作还未执行）

**账号整体评分**（0-100分）：
- 内容质量分（25%）：基于内容深度、原创性、表现
- 选题适配分（20%）：选题与定位匹配度、受众反馈
- 发布节奏分（15%）：频率稳定性、时段合理性
- 互动健康分（20%）：回复率、互动深度
- 账号增长分（20%）：粉丝增长、互动趋势

评分趋势可视化（近7天/30天折线），评分下降自动预警。

---

#### 模块⑥：执行追踪闭环

**追踪逻辑**：
1. 每周生成行动建议后，记录每个 action 的状态（待执行/进行中/已完成/已放弃）
2. 下周复盘时，自动检查每个 action 的执行情况：
   - **是否执行**：通过数据变化判断（如"回复率提升"→看回复率数据）
   - **是否带来改善**：执行后相关指标是否有正向变化
3. 对未执行的 action，分析原因（没时间/不会做/不认同/资源不足）
4. 对执行了但没改善的 action，分析原因（动作不对/执行不到位/外部因素）
5. 将追踪结果反馈到下周的诊断和建议中，形成闭环

**追踪输出**：
- 上周建议执行率统计
- 每个 action 的执行状态和效果验证
- 未执行/无改善的原因分析
- 闭环改进建议

---

### 2.3 人工审核节点

遵循题目基本要求"涉及对外发布或账号操作时，必须设置人工确认"：

| 节点 | 人工操作 | 系统能力 |
|------|----------|----------|
| 账号配置 | 确认/修改受管账号列表 | 推荐账号，人工确认 |
| 诊断结果确认 | Leader 审核诊断是否准确，可修正 | 自动诊断，人工校准 |
| 行动建议确认 | Leader 与运营同学确认下周动作 | 生成建议，人工最终确认 |
| 1on1 沟通 | Leader 使用提纲进行沟通，可调整 | 生成提纲，人工使用 |
| 报告分发 | 确认报告内容后分发给团队 | 自动生成，人工确认后分发 |
| 账号操作 | 任何发布、回复、改资料等操作必须人工执行 | Agent 只做分析和建议，不自动操作账号 |

### 3.2 核心技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| Agent 编排 | 自研轻量工作流（可扩展 LangGraph） | Demo 阶段轻量够用，6步顺序编排 |
| LLM | GPT-4o / 本地开源模型（可切换） | 问题归因和行动建议需要较强的推理能力 |

| 指标计算 | Python 标准库（statistics/numpy可选） | 评分、趋势、异常检测 |
| 数据存储 | JSON 文件 + SQLite（可选） | 轻量、本地可运行、无需外部依赖 |
| 接口层 | CLI + FastAPI（可选） | Demo 用 CLI，生产可扩展 HTTP API |

```python
def attribute_problem(account_data, content_samples):
    problems = []

    # 1. 内容质量问题
    if account_data.avg_engagement_rate < BENCHMARK * 0.5:
        if content_quality_score(content_samples) < 60:
            problems.append({
                "dimension": "内容质量",
                "confidence": 0.8,
                "evidence": [...]
            })

    # 2. 选题问题
    if topic_diversity > 0.7:  # 选题过于分散
        problems.append({"dimension": "选题", ...})
    if topic_relevance_to_positioning < 0.6:
        problems.append({"dimension": "选题", ...})

    # 3. 定位问题
    if domain_consistency < 0.5:  # 内容领域跳跃
        problems.append({"dimension": "定位", ...})

    # 4. 发布节奏问题
    if posting_frequency_cv > 0.8:  # 发布频率变异系数大
        problems.append({"dimension": "发布节奏", ...})
    if peak_posting_hour not in audience_active_hours:
        problems.append({"dimension": "发布节奏", ...})

    # 5. 互动问题
    if reply_rate < 0.01:  # 回复率低于1%
        problems.append({"dimension": "互动", ...})
    if avg_response_time > 24h:
        problems.append({"dimension": "互动", ...})

    # 6. 账号健康问题
    if follower_growth_rate < -0.01:  # 持续掉粉
        problems.append({"dimension": "账号健康", ...})

    return problems
```

### 3.4 账号评分算法

```python
def calculate_account_score(account_data):
    # 内容质量分 (25%)
    content_score = calculate_content_quality(account_data.contents) * 0.25

    # 选题适配分 (20%)
    topic_score = calculate_topic_relevance(account_data) * 0.20

    # 发布节奏分 (15%)
    rhythm_score = calculate_posting_rhythm(account_data) * 0.15

    # 互动健康分 (20%)
    engagement_score = calculate_engagement_health(account_data) * 0.20

    # 账号增长分 (20%)
    growth_score = calculate_growth(account_data) * 0.20

    total = content_score + topic_score + rhythm_score + engagement_score + growth_score

    return {
        "total": round(total, 1),
        "breakdown": {
            "content_quality": round(content_score, 1),
            "topic_relevance": round(topic_score, 1),
            "posting_rhythm": round(rhythm_score, 1),
            "engagement_health": round(engagement_score, 1),
            "growth": round(growth_score, 1),
        },
        "level": "excellent" if total >= 80 else "good" if total >= 60 else "needs_improvement" if total >= 40 else "critical"
    }
```

## 五、上线效果与迭代路线

### 5.1 预期效果

| 阶段 | 时间 | 目标 |
|------|------|------|
| MVP | 第1-2周 | 单团队3个账号试用，验证诊断准确率和建议可执行性 |
| 优化 | 第3-4周 | 积累4周复盘数据，校准归因规则和评分权重 |
| 规模化 | 第2月 | 支持10+账号矩阵，多团队复用 |
| 智能化 | 第3月 | 实现全自动每日监控+异常预警，行动建议执行率追踪自动化 |

### 5.2 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 诊断不准确，误导行动 | 运营方向跑偏 | 规则引擎+LLM双归因，Leader人工审核确认，持续校准规则 |
| 行动建议不可执行 | 复盘流于形式 | SMART原则强制约束，标注难度和所需资源，与运营同学确认 |
| 数据采集受限 | 分析不全面 | 支持多数据源备份，关键指标缺失时明确标注"数据不足" |
| 评分体系不合理 | 误导账号运营 | 5维度加权可配置，根据团队实际情况调整权重，持续验证 |
| 1on1提纲太机械 | 沟通不自然 | 提纲作为参考框架，Leader可灵活调整，重点是结构化不遗漏 |

## 六、人工审核与合规说明

1. **Agent 不自动操作账号**：只做分析、建议和报告，任何发布、回复、改资料等操作必须人工执行
2. **诊断结果人工确认**：Leader 审核诊断是否准确，可修正后再生成建议
3. **行动建议双向确认**：Leader 与运营同学 1on1 时共同确认下周动作，不单方面下达
4. **报告分发人工确认**：每日/每周报告生成后，人工确认内容无误再分发
5. **数据使用合规**：仅使用公开可访问的账号数据，遵守平台 API 使用条款
